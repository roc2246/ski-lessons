This document describes the MongoDB schema, indexes, and key business logic related to data access.

## Collections

### User Collection

Stores registered users with authentication credentials.

| Field | Type | Required | Unique | Indexed | Notes |
|-------|------|----------|--------|---------|-------|
| `_id` | ObjectId | Yes | Yes | Yes | Auto-generated by MongoDB |
| `username` | String | Yes | Yes | Yes | 3+ characters, alphanumeric/underscore |
| `password` | String | Yes | No | No | Bcrypt hashed (salt rounds: 12) |
| `admin` | Boolean | Yes | No | No | Default: `false`; set during registration |
| `createdAt` | Date | Yes | No | No | Auto-generated, ISO timestamp |
| `updatedAt` | Date | Yes | No | No | Auto-generated, ISO timestamp |

**Indexes:**

```javascript
db.users.createIndex({ username: 1 }, { unique: true })
```

**Example Document:**

```json
{
  "_id": ObjectId("507f1f77bcf86cd799439011"),
  "username": "john_doe",
  "password": "$2b$12$...",
  "admin": false,
  "createdAt": ISODate("2025-01-15T10:30:00Z"),
  "updatedAt": ISODate("2025-01-15T10:30:00Z")
}
```

### Lesson Collection

Stores ski lessons with availability and assignment status.

| Field | Type | Required | Unique | Indexed | Notes |
|-------|------|----------|--------|---------|-------|
| `_id` | ObjectId | Yes | Yes | Yes | Auto-generated by MongoDB |
| `type` | String (enum) | Yes | No | No | beginner, intermediate, advanced, expert |
| `date` | String (YYYY-MM-DD) | Yes | No | Yes | UTC date, normalized at service layer |
| `timeLength` | String (enum) | Yes | No | No | 9-12, 1-4, 9-4 |
| `guests` | Number | Yes | No | No | 1-12 students |
| `assignedTo` | ObjectId (ref: User) | No | No | Yes | null = unassigned; references User._id |
| `createdAt` | Date | Yes | No | No | Auto-generated, ISO timestamp |
| `updatedAt` | Date | Yes | No | No | Auto-generated, ISO timestamp |

**Indexes:**

```javascript
db.lessons.createIndex({ date: 1 })
db.lessons.createIndex({ assignedTo: 1 })
db.lessons.createIndex({ date: 1, assignedTo: 1 })
```

**Constraints (enforced at schema level):**

```javascript
// Enum validation at database
type: { type: String, enum: ["beginner", "intermediate", "advanced", "expert"], required: true }
timeLength: { type: String, enum: ["9-12", "1-4", "9-4"], required: true }
```

**Example Document (Unassigned):**

```json

  "date": "2025-02-15",

```

**Example Document (Assigned):**

### BlacklistedToken Collection

Stores revoked JWT tokens to prevent reuse after logout.

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `_id` | ObjectId | Yes | Auto-generated by MongoDB |
| `token` | String | Yes | Full JWT string (unique index) |
| `expiresAt` | Date | Yes | Token expiration timestamp (TTL index) |

**Indexes:**

```javascript
db.blacklistedtokens.createIndex({ expiresAt: 1 }, { expireAfterSeconds: 0 })
// TTL index: documents auto-delete when expiresAt passes
db.blacklistedtokens.createIndex({ token: 1 }, { unique: true })
```

**Example Document:**

```json
{
  "_id": ObjectId("507f1f77bcf86cd799439014"),
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "expiresAt": ISODate("2025-01-15T11:30:00Z")
}
```

**Lifecycle:**
- Token added on logout
- TTL index automatically deletes after `expiresAt` (tokens expire in 1 hour)
- Query before use to prevent token reuse

## Key Business Logic

### Lesson Conflict Detection

The system prevents instructors from being double-booked.

**Definition:** Two lessons conflict if they:
1. Occur on the **same date** (YYYY-MM-DD)
2. Have **overlapping time windows**

**Time Window Overlap Map:**

| Lesson A | Lesson B | Conflict? |
|----------|----------|-----------|
| 9-12 | 9-12 | ✅ Yes |
| 9-12 | 1-4 | ❌ No |
| 9-12 | 9-4 | ✅ Yes |
| 1-4 | 1-4 | ✅ Yes |
| 1-4 | 9-4 | ✅ Yes |
| 9-4 | 9-4 | ✅ Yes |

**Implementation:**

```typescript
// server/src/services/lessons.ts
const CONFLICTING_TIME_LENGTHS: Record<string, Set<string>> = {
  "9-12": new Set(["9-12", "9-4"]),
  "1-4": new Set(["1-4", "9-4"]),
  "9-4": new Set(["9-12", "1-4", "9-4"]),
};

function hasTimeWindowConflict(existing: Lesson, proposed: Lesson): boolean {
  return existing.date === proposed.date &&
    CONFLICTING_TIME_LENGTHS[existing.timeLength]?.has(proposed.timeLength) ?? false;
}
```

**Query Example:**

Find all lessons for a user on a given date:

```javascript
db.lessons.find({
  assignedTo: ObjectId("507f1f77bcf86cd799439011"),
  date: "2025-02-15"
})
```

Check for conflicts:

```javascript
db.lessons.find({
  date: "2025-02-15",
  timeLength: { $in: ["9-12", "9-4"] },
  assignedTo: ObjectId("507f1f77bcf86cd799439011")
})
```

### Date Normalization

All dates are stored as **UTC YYYY-MM-DD strings** for consistency across time zones.

**Normalization Logic** (`server/src/services/lessons.ts`):

```typescript
function normalizeDateString(value: unknown): string {
  if (typeof value === "string") {
    // Already a string; extract YYYY-MM-DD
    const match = value.match(/^\d{4}-\d{2}-\d{2}/);
    return match ? match[0] : "";
  }

  if (value instanceof Date) {
    // Convert Date to UTC YYYY-MM-DD
    return value.toISOString().slice(0, 10);
  }

  return "";
}
```

**Why:** Lesson dates must be time-zone agnostic. "February 15" should be the same date for all users regardless of their local time zone.

### Cascading Delete

When a user is deleted, all lessons assigned to that user are unassigned.

**Query:**

```javascript
db.lessons.updateMany(
  { assignedTo: ObjectId("507f1f77bcf86cd799439011") },
  { $set: { assignedTo: null } }
)
```

**Implementation** (`server/src/services/auth.ts`):

```typescript
export async function deleteUser(username: string): Promise<unknown> {
  const result = await UserModel.deleteOne({ username });
  return result;
}

// Called from controller after unassigning lessons
export async function selfDeleteAccount(req, res) {
  const { userId } = req.user;
  await unassignAllLessons(userId);  // First: unassign all lessons
  await deleteUser(username);        // Then: delete user
  res.json({ message: "User deleted" });
}
```

### Lean Queries

For read-only operations, use `.lean()` to skip Mongoose document overhead.

**Example:**

```typescript
// Fetch unassigned lessons (read-only)
const lessons = await LessonModel.find({ assignedTo: null }).lean();
// Returns plain JS objects, not Mongoose documents
```

**When to use:**
- ✅ GET endpoints (reading data)
- ❌ POST/PUT/PATCH endpoints (modifying data requires Mongoose document methods)

## Querying Best Practices

### Find Unassigned Lessons

```javascript
db.lessons.find({ assignedTo: null })
```

### Find Lessons for a User on a Date

```javascript
db.lessons.find({
  assignedTo: ObjectId("507f1f77bcf86cd799439011"),
  date: "2025-02-15"
})
```

### Find All Lessons (Populated with User Info)

```javascript
db.lessons.aggregate([
  {
    $lookup: {
      from: "users",
      localField: "assignedTo",
      foreignField: "_id",
      as: "instructor"
    }
  }
])
```

### Count Lessons by Type

```javascript
db.lessons.aggregate([
  {
    $group: {
      _id: "$type",
      count: { $sum: 1 }
    }
  }
])
```

## Index Performance

Indexes improve query speed. Current indexes:

| Collection | Index | Purpose |
|------------|-------|---------|
| users | `{ username: 1 }` (unique) | Fast username lookup on login/register |
| lessons | `{ date: 1 }` | Fast date-range queries |
| lessons | `{ assignedTo: 1 }` | Fast user lesson lookups |
| lessons | `{ date: 1, assignedTo: 1 }` | Fast conflict detection |
| blacklistedtokens | `{ expiresAt: 1 }` (TTL) | Auto-cleanup of expired tokens |

**Monitor index performance:**

```javascript
// Check index sizes
db.lessons.aggregate([ { $indexStats: {} } ])

// Check query execution time
db.lessons.find({ date: "2025-02-15" }).explain("executionStats")
```

## Schema Enforcement

Mongoose schemas enforce validation at insert/update time:

```typescript
const lessonSchema = new Schema({
  type: { type: String, enum: ["beginner", "intermediate", "advanced", "expert"], required: true },
  timeLength: { type: String, enum: ["9-12", "1-4", "9-4"], required: true },
  date: { type: String, required: true },
  guests: { type: Number, required: true, min: 1, max: 12 },
  assignedTo: { type: Schema.Types.ObjectId, ref: "User", default: null },
});
```

**Guarantees:**
- ✅ `type` must be one of 4 values
- ✅ `timeLength` must be one of 3 values
- ✅ `guests` must be 1-12
- ✅ `assignedTo` defaults to null (unassigned)
